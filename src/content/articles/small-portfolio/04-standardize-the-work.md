# Standardize the Work, Not the Places: What Should Be the Same Everywhere

Owners who grow past a few sites often feel pulled between two instincts. One says every location should run the same way. The other says every location is different and needs its own approach. Both are partly right. This article gives you a same-or-local decision table for sorting each part of your operation, and a site fact sheet that keeps local differences written down instead of remembered.

## Two ways to get standardization wrong

Standardization fails in two familiar directions.

**Too little.** Each site runs on its own habits. Month-end reports arrive in different formats. Work orders are logged in a notebook at one site and in a text thread at another. The owner learns about problems late, because there is no common place for them to appear. This is where most small portfolios start, and it is a reasonable place to start. Each site grew the way it needed to.

**Too much.** The owner writes one procedure and applies it everywhere without regard to the ground. A snow-removal schedule written for a building in a cold town gets applied to one in a mild town. A dental office with two operatories is asked to follow the staffing template of an office with eight. The standard is followed on paper and worked around in practice.

The way through is to separate two things that are easy to blur: the work and the place. The work is the set of questions every site must answer and the routine for answering them. The place is the set of facts that make each site what it is.

## Standard questions, site-specific facts

The rule for this article fits in one sentence: standardize the questions and the routine, record the facts locally.

Consider the illustrative owner of six small-bay industrial buildings. Every building should answer the same questions each month. Which bays are leased and on what terms? What dates are coming due? What work is open, and how long has it been open? What did the building collect and spend? Those questions, the format of the answers, and the day they are due should be identical across all six.

The facts behind the answers differ. One building has a shared truck court; another has individual dock doors. One has a roof under warranty; another has a roof near the end of its life. One sits on a parcel with a recorded access agreement; another does not. Those facts belong to the building and should be recorded for that building, in a standard place, without being forced into a template that does not fit.

The illustrative dental group with four offices follows the same pattern. Every office answers the same questions: how full was the schedule, what was collected against what was billed, which equipment is due for service, which staff credentials renew in the next six months. The facts differ: the number of operatories, the equipment models, the lease terms, the local vendors. The questions are shared. The facts are local.

## The same-or-local decision table

The decision table is the main tool of this article. List each part of your operation and decide whether it should be the same everywhere, set locally within a shared frame, or left fully local.

| Element | Same everywhere | Local within a shared frame | Fully local |
|---|---|---|---|
| Chart of accounts and denominators | ✓ | | |
| Monthly report format and due date | ✓ | | |
| Rollup definitions | ✓ | | |
| Work order priorities and target times | ✓ | | |
| Critical-dates record structure | ✓ | | |
| Approval limits for spending | | Shared tiers, site-level amounts where justified | |
| Vendor list | | Shared preferred vendors, local backups | |
| Preventive maintenance schedule | | Shared task list, local frequencies | |
| Site layout, recorded constraints, access | | | ✓ |
| Tenant or patient mix | | | ✓ |
| Local relationships and contacts | | | ✓ |

Three tests help sort an element that is not obvious.

1. **Does the owner compare it across sites?** If yes, it belongs in the "same everywhere" column. Anything that feeds the rollup falls here.
2. **Does the physical place change the right answer?** If yes, it belongs in one of the local columns. Climate, layout, recorded instruments, and equipment all change right answers.
3. **Would a new site manager need it on day one?** If yes, write it down, whichever column it falls in. Local facts left unwritten are the hardest thing to hand over.

The middle column does most of the practical work. A shared preventive maintenance list with local frequencies lets the industrial owner compare whether each building's roof was inspected, while allowing the older roofs to be inspected more often. Shared approval tiers with site-level amounts let the dental group keep one approval routine, while allowing a larger office to hold a higher limit for supplies.

## The site fact sheet

Local facts need a home. The site fact sheet is a one-page record, the same layout for every site, filled with facts that are specific to that site.

| Section | What it records | Industrial example | Dental example |
|---|---|---|---|
| Identity | Legal name, address, owner of record | Building owner entity, parcel number | Office entity, suite address |
| Physical | Area, layout, systems, age of major components | Leasable area from the denominator register, roof type and age | Operatory count, major equipment list |
| Recorded constraints | Easements, use limits, approvals that govern the site | Recorded access agreement with the neighboring parcel | Landlord use restrictions in the office lease |
| Dates | The site's standing dated obligations | Roof warranty end, service contract renewals | Equipment service dates, lease renewal window |
| Vendors | Local vendors and backups | Door repair, sweeping, landscaping | Equipment service, courier, cleaning |
| Contacts | People and roles | Site lead, broker | Office manager, lead hygienist |
| Known quirks | What a newcomer would not guess | A dock door that sticks in cold weather | A scheduling system that runs one day behind on insurance checks |

The layout is standard. The content is entirely local. Anyone who opens a fact sheet knows where to look, and what they find is true of that site alone.

Recorded constraints deserve particular care. Whether a recorded instrument limits what a site may do is a question for counsel when the meaning matters. The fact sheet records that the instrument exists, where it is filed, and who has read it.

AI can help keep fact sheets current. It can extract dates and parties from a new lease or service contract, compare a fact sheet against the records it summarizes and flag a mismatch, and draft an update for the site lead to review. It does not decide what a site's constraints mean, and it does not change a fact sheet without a person approving the change.

### The view from Arnould Blvd

Command Platform, the software that runs On The Blvd Shopping Center, shows this split in its structure. The platform is organized as numbered sheets, and each sheet answers one operating question: what is leased, what is due, what is open, what is required. Those are standard questions. Any site in any portfolio needs those same questions answered in the same way. The facts on each sheet are not standard at all. The site plan is drawn from this property's own recorded plat, with its two buildings on 4.84 acres and its recorded constraints placed where the plat puts them. The questions travel. The plat does not. That is the pattern this article recommends: a shared set of questions, answered from the facts of one specific place.

## Rolling a standard out

A standard that arrives as a memo tends to be followed for a month. A few habits help it last.

- **Start with one element.** The monthly report format is a good first choice, because every site feels its benefit quickly.
- **Write it with a site lead.** Draft the standard with the person who will follow it. They will find the local exception before it becomes a workaround.
- **Record exceptions on the fact sheet.** When a site needs a different answer, write the reason down. An exception on the record is a decision. An exception off the record is drift.
- **Review twice a year.** Move elements between columns when experience shows they belong elsewhere.

## The practical next step

1. List ten elements of your operation and sort each into one of the three columns of the decision table.
2. Pick one "same everywhere" element and write its standard with one site lead this month.
3. Draft a site fact sheet for your most complex site, using the seven sections above.
4. Note every recorded constraint on that sheet with where it is filed and who has read it.
5. Schedule a review in six months to move elements between columns based on what you learned.
